# Courier

Courier connects people who need an item with travelers already going that way. The app uses Next.js App Router, TypeScript, Tailwind CSS 4, PostgreSQL, and Prisma ORM 7.

## Local setup

1. Copy `.env.example` to `.env` if needed and set `DATABASE_URL` and a private `AUTH_SECRET`.
2. Install dependencies with `npm install`. Prisma Client is generated by the npm `postinstall` hook.
3. Start the app with `npm run dev`.
4. Apply schema changes with `npx prisma migrate dev --name <migration-name>`.

Deployments should apply committed migrations with `npx prisma migrate deploy` as a release step. The app build generates Prisma Client but does not apply migrations. The project stays on Prisma 7.

## Authentication

Authentication uses Auth.js Credentials with Courier-managed email/password accounts. Registration is a REST endpoint at `POST /api/v1/auth/register`. Passwords are hashed with Argon2id; sign-in uses JWT sessions and a PostgreSQL-backed per-email failed-attempt limit. Set `AUTH_SECRET` to a long random value before running the app.

Auth.js Credentials does not create or persist users by itself, so Courier stores users and password hashes in the existing `User` table. Email verification, account recovery, and additional network-level rate limiting are launch requirements before opening registration publicly.

## REST API

All browser and server-to-server operations use HTTP route handlers under `/api/v1`; the app does not use Server Actions for API requests. Request, itinerary, matching, agreement, and registration endpoints are documented in [openapi.yaml](./openapi.yaml). Protected endpoints scope data to the authenticated owner.

Matching checks whether the request origin and destination appear in order along a future itinerary, including declared intermediate stops. If both locations have coordinates, a waypoint within 30 km qualifies; otherwise normalized city and country names must match. A request's `neededBy` date is the latest acceptable itinerary arrival date. Matches remain suggestions until the traveler expresses interest.

Agreement endpoints start an agreement from an interested match, record versioned item-cost-plus-fee terms, require requester acceptance of the current revision, and prevent ordinary cancellation after funding. Funds cannot be released until requester delivery confirmation is implemented and recorded.

The health endpoint is available at `http://localhost:3000/api/v1/health`. It reports application liveness and does not verify database connectivity.

## UI conventions

- Use Tailwind utilities for page and component layout, spacing, color, typography, and interaction states.
- Keep global CSS limited to theme tokens, base browser settings, and shared keyframes.
- Keep the application canvas white. Use Courier green for primary actions and quiet gold accents for route and status details.
- Use borders, spacing, color, and subtle motion for depth; do not use drop shadows or box shadows.
- Respect reduced-motion preferences for all nonessential animation.

## Project structure

- `src/app` - pages and REST route handlers.
- `src/auth.ts` and `src/app/api/auth/[...nextauth]` - Auth.js configuration and route handler.
- `src/lib/http` - response envelopes, request IDs, validation, and route error conversion.
- `src/lib/domain` - request, itinerary, authentication, and agreement services.
- `src/lib/auth` - password hashing, login throttling, auth boundary, and session helpers.
- `src/lib/db` - Prisma client boundary.
- `src/lib/logging` - structured server log helper.
- `prisma/schema.prisma` - marketplace and local authentication models.
- `prisma.config.ts` - Prisma 7 schema, migration, and generation config.
- `openapi.yaml` - current REST endpoint contract.
- `plan.md` - staged implementation roadmap.
